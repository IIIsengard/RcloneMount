# RcloneMount leads on uptime, lags on visibility

Research date: 2026-11-24. Audience: the RcloneMount developer.

RcloneMount's closest rivals are three rclone GUIs: **RClone Manager** (free, GPL, very active), **Rclone UI** (now in the official `rclone` GitHub org, freemium) and **RcloneView** (closed freemium, from the company behind NetDrive). The commercial mount tools (RaiDrive, NetDrive, Mountain Duck, CloudMounter, ExpanDrive) only mount drives. None of them has a transfer queue or a scheduler. RcloneMount's clearest edge is that it remounts by itself after sleep, network loss or a detached drive, and does it for free. RClone Manager's docs say it tries once and never retries. RcloneView charges for "auto re-mount on startup" and for scheduling. The biggest gaps are about what the user can see, not about feature count. The app cannot show pending mount uploads. It does not support an encrypted `rclone.conf` at all. A failed scheduled job only writes to the activity log. It has no help for the 2026 Google Drive client_id change. Its mount defaults (a 15 s directory cache on every remote, plus an uncapped `full` VFS cache) go against what forum experts advise. Most of these are small jobs on top of the stats poller and tray balloons the app already has.

Two structural shifts matter. First, RaiDrive (2026.10.0) and NetDrive (4.0) both moved onto WinFsp in October and November 2026. RcloneMount therefore cannot win on the driver. It has to win on reliability, licence and rclone's backend range. Second, the "official" choice has consolidated. The rclone project now bundles `rclone gui` and hosts Rclone UI in its org, and Rclone UI ships fast. Release 3.6.0 (2026-06-05) fixed "mounting on startup". Release 3.7.0 (2026-07-11) added remote-reconnect detection, a notifications engine, native OS scheduling and a rclone version manager ([forum 52568](https://forum.rclone.org/t/52568)). Rclone UI is the rival that is closing in on RcloneMount's strengths.

## Ten complaints recur across the category, led by silent state

The ranking weighs severity first, then how often the complaint appears (views, reactions, repeats), then how recent it is. Forum counts come from forum.rclone.org searches limited to posts after 2025-01-01 ([forum search](https://forum.rclone.org/search.json), queried 2026-11-24).

1. **Mounts that drop, hang or go stale while the app says "mounted".** A WebDAV mount on Windows 11 drops after about 5 minutes idle; the bug is open and waiting on upstream ([rclone #9482, 2026-06-01](https://github.com/rclone/rclone/issues/9482)). Windows hung when a remote became unreachable. The user then wrote their own tray app that mounts through `rcd` and watches for the remote going offline ([forum 54067, 2026-07-23](https://forum.rclone.org/t/54067)). RClone Manager disappears after Windows suspend ([#17, 2025-09-11](https://github.com/Zarestia-Dev/rclone-manager/issues/17)), and on macOS it shows "Mounted" for dead mounts ([#5, 2025-06-16](https://github.com/Zarestia-Dev/rclone-manager/issues/5)). Mountain Duck "does not report disconnected mount" ([#17645, 2025-11-16](https://github.com/iterate-ch/cyberduck/issues/17645)). NetDrive only fixed "Connection refused" after wake in 4.0 ([2026-11-17](https://accounts.bdrive.com/product_history/NetDrive3/)).
2. **Data integrity, and not knowing when an upload is really done.** Windows reported a copy finished at "6 gb per second" while the file was not yet on the remote. A moderator suggested looking for a GUI that shows `vfs/stats` ([forum 53697, 2026-04-18](https://forum.rclone.org/t/53697)). NetDrive's manual admits Explorer can finish while the upload is still running ([manual](https://www.netdrive.net/wiki/netdrive/application-manual/add-configure-drive/)). NetDrive had a cluster of corruption reports in January 2026 ([Bdrive forum](https://support.bdrive.com/c/netdrive3/7)). RaiDrive returned wrong 16–32 KB blocks over Synology WebDAV ([2026-11-02](https://with.raidrive.com/latest)). Mountain Duck 5.0.2 emptied files ([#17516, 2025-09-26](https://github.com/iterate-ch/cyberduck/issues/17516)). On Windows, rclone's VFS cache could silently lose atomic temp-then-rename saves ([forum 54004, 2026-07-04](https://forum.rclone.org/t/54004)).
3. **Re-authentication churn, led by Google Drive's client_id retirement.** rclone's shared Drive client_id "will stop working in 2026", so users must create their own ([forum 54005, 2026-07-06, 5,848 views](https://forum.rclone.org/t/54005); [rclone #9580, 2026-07-07](https://github.com/rclone/rclone/issues/9580)). Users find this hard ([forum 54145, 2026-08-17, 1,692 views](https://forum.rclone.org/t/54145); [forum 54279, 2026-09-27, 1,248 views](https://forum.rclone.org/t/54279)). iCloud's 30-day token is a second source of pain ([rclone #8587, +144, 2025-06-06](https://github.com/rclone/rclone/issues/8587)). RaiDrive makes users sign in on every connect ([docs](https://docs.raidrive.com/gui/options/general/)).
4. **The VFS cache filling the disk.** A 700 GB upload through a mount filled a 215 GB SSD ([forum 53478, 2026-02-28, 1,077 views](https://forum.rclone.org/t/53478)). `--vfs-cache-max-size` "is not a hard limit" ([forum 53318, 2026-01-20](https://forum.rclone.org/t/53318)). NetDrive's most-viewed forum thread asks for more cache settings ([2025-12-01, 1,862 views](https://support.bdrive.com/c/netdrive3/7)).
5. **Slow browsing and Explorer freezes.** A mounted Google Drive took over 30 s to open files ([forum 54253, 2026-09-16, 1,095 views](https://forum.rclone.org/t/54253)). CloudMounter took 15 s to open a folder ([Trustpilot, 2025-11-21](https://ca.trustpilot.com/review/cloudmounter.net)).
6. **Schedules that silently never run.** This is Rclone UI's most repeated issue ([#113, 2025-12-16](https://github.com/rclone/rclone-ui/issues/113); [#141, 2026-01-28](https://github.com/rclone/rclone-ui/issues/141); [#215, 2026-06-01](https://github.com/rclone/rclone-ui/issues/215)). Scheduled tasks also fail without a saved config password ([#250, 2026-10-03](https://github.com/rclone/rclone-ui/issues/250)). Users ask for failure alerts, and ncw (rclone's maintainer) leaves that to GUIs and hooks ([forum 54283, 2026-09-28](https://forum.rclone.org/t/54283)).
7. **Paywalls and licence friction on basic features.** RaiDrive users complain about ads and read-only services, including on paid plans ([AlternativeTo, 2024-07-07 and 2026-11-03](https://alternativeto.net/software/raidrive/about/)). Rclone UI users hit licence activation limits ([#230, 2026-07-21](https://github.com/rclone/rclone-ui/issues/230)). ExpanDrive charged again on "perpetual" licences ([Trustpilot, 2025-03-05](https://www.trustpilot.com/review/expandrive.com)). Air Explorer users dislike the subscription ([Trustpilot, 2026-04-03](https://fi.trustpilot.com/review/airexplorer.net)).
8. **Update regressions.** RaiDrive 2026.10.0 stopped connecting to a Synology NAS ([2026-10-28](https://with.raidrive.com/latest)). NetDrive 3.19.7 brought connection faults ([2026-04-15](https://support.bdrive.com/c/netdrive3/7)). rclone 1.76.0 hangs on UNC paths, and the reporter stayed on 1.75.2 ([forum 54517, 2026-11-17](https://forum.rclone.org/t/54517)). RClone Manager settings broke after an update ([#149, 2026-03-18](https://github.com/Zarestia-Dev/rclone-manager/issues/149)).
9. **Autostart and elevation setup.** A drive was invisible because rclone ran elevated ([forum 52120, 2025-08-01](https://forum.rclone.org/t/52120)). Users want mounts that start by themselves ([forum 53911, 2026-06-10, 1,041 views](https://forum.rclone.org/t/53911)). A guide to running rclone as a Windows service drew 1,200 views ([forum 53012, 2025-11-20](https://forum.rclone.org/t/53012)).
10. **Confusing UIs.** A user called RClone Manager confusing and moved to paid RcloneView ([forum, 2026-02-17](https://forum.rclone.org/t/rclone-manager-a-new-cross-platform-user-frienly-gui/53051)). Air Explorer is "hard to learn" ([Trustpilot, 2026-04-03](https://fi.trustpilot.com/review/airexplorer.net)). Rclone UI's tray icon is "almost clear so it is easy to miss" ([#110, 2025-12-15](https://github.com/rclone/rclone-ui/issues/110)).

A related fear also comes up: destructive sync and bisync. A user lost years of photos to `rclone sync` ([forum 49929, 2025-02-07](https://forum.rclone.org/t/49929)), and there is an open request that sync should not delete by default ([rclone #8922, 2025-10-25](https://github.com/rclone/rclone/issues/8922)). RcloneMount already covers most of this (see "already wins").

## The code check confirms nine of thirteen candidate gaps

**1. Pending mount uploads and a guard on exit, unmount and update.** *Competitors:* NetDrive added upload pop-ups in 3.18 (2025-02-09) and auto-retry in 4.0 (2026-11-17) ([product history](https://accounts.bdrive.com/product_history/NetDrive3/)). RClone Manager added a tray upload indicator ([#61](https://github.com/Zarestia-Dev/rclone-manager/issues/61), requested 2025-12-12, shipped 2026-03-11). CryptBridge warns before quitting with uploads pending ([forum, 2026-10-29](https://forum.rclone.org/t/cryptbridge-free-windows-tray-app-that-mounts-rclone-crypt-vaults-as-drive-letters/54415)). Mountain Duck 5 has an Activity window that lists pending syncs ([2025-08-19](https://blog.cyberduck.io/2025/08/19/mountain-duck-5/)). *Why users care:* complaint #2 above ([forum 53697, 2026-04-18](https://forum.rclone.org/t/53697)), plus an open request for mount progress ([rclone #8330, 2025-01-23](https://github.com/rclone/rclone/issues/8330)). Today RcloneMount gives up on a graceful stop after 6 s and kills rclone. Unfinished uploads only resume "next time rclone is run with the same flags" ([mount docs](https://rclone.org/commands/rclone_mount/)), and the user is never told. *Build:* call `vfs/stats` (`uploadsInProgress`, `uploadsQueued`) in the existing 2 s poll. Show "N uploading, M queued" on the mount row and in the tray tooltip or icon. Before Exit, Unmount and Install update, confirm when the count is above zero. Hold off auto-update and the auto-recover kill while a responsive mount still has uploads pending.

**2. Encrypted `rclone.conf`.** *Competitors:* RClone Manager detects an encrypted config, asks once and stores the password in Windows Credential Manager ([#212, 2026-05-26](https://github.com/Zarestia-Dev/rclone-manager/issues/212)). Rclone Explorer keeps it in memory and passes it as an environment variable ([README](https://github.com/Jackpison/RcloneExplorer)). Rclone Browser, REM ([#18, 2025-09](https://github.com/liriliri/rem/issues/18)) and CryptBridge also handle it. *Why users care:* "config password" and "crypt password" each return 50+ forum topics since 2025. A user on a shared desktop asked for exactly this protection ([forum 52900, 2025-10-25](https://forum.rclone.org/t/52900)). The original RcloneTray could not mount with a protected config ([#8](https://github.com/dimitrov-adrian/RcloneTray/issues/8), 2020, older), which is RcloneMount's position today. *Build:* detect the encrypted header. Prompt once, with a "remember on this PC" option stored through DPAPI or Credential Manager. Set `RCLONE_CONFIG_PASS` in the environment of every child (mount, job, config calls, terminal), never on the command line. Learn from Rclone UI #250: say plainly that auto-mount and schedules need the remembered password. Warn on backup when the config is not encrypted, because the backup zip then holds tokens in plain text.

**3. Job failure notifications.** *Competitors:* RcloneView sends a free system notification when a job completes ([pricing](https://rcloneview.com/src/pricing.html)). Rclone UI 3.7.0 posts to Slack, Discord, Telegram, email or a webhook ([forum 52568, 2026-07-11](https://forum.rclone.org/t/52568)). RClone Manager has alert rules ([docs](https://github.com/Zarestia-Dev/rclone-manager-website/blob/HEAD/public/docs/user-guide/alerts-and-notifications.md)). Rclone Explorer adds a sound on failure. *Why users care:* complaint #6. A nightly backup that fails into a log file is found days late. *Build:* reuse `Notify` when a scheduled or queued job ends Failed. Let failure balloons through even when Notifications is muted, the way serious app errors already are. Keep a red tray badge until the user opens the Jobs tab. A single webhook URL is the optional M step.

**4. Google Drive client_id onboarding.** *Competitors:* none found with a guided flow, so this is a chance to lead. rclone plans to push users in its own `rclone config` wizard ([#9580, 2026-07-07](https://github.com/rclone/rclone/issues/9580)). RcloneMount users never see that wizard, because the app has its own remote editor. *Why users care:* complaint #3. The [Drive docs](https://rclone.org/drive/) say the shared id "will stop working during 2026". They also say an app left in Testing gets grants that "expire after a week". The shared id is rate-limited as well ([forum 50553, 2025-03-20](https://forum.rclone.org/t/50553)). The cut-off date is open: on 2026-09-19 ncw wrote "Google have gone silent" ([forum 54005](https://forum.rclone.org/t/54005)). *Build:* flag Drive (and Google Photos) remotes with an empty `client_id`. Add a short steps page that links to rclone's guide and warns that the app must be published. Add fields for id and secret, then run the existing Reconnect.

**5. Polling-aware directory cache and a refresh action.** *Competitors:* RClone Manager builds per-mount VFS profiles from flags it reads over rc ([mounting docs](https://github.com/Zarestia-Dev/rclone-manager-website/blob/HEAD/public/docs/user-guide/mounting.md)). RaiDrive has a per-drive remote-change refresh interval ([docs](https://docs.raidrive.com/gui/options/advanced/)). *Why users care:* forum experts advise against short dir-cache times on polling remotes. On OneDrive: "Forcing to rescan remote dirs every 20s definitely does not help with performance (and is not needed anyway)" ([forum 53838, 2026-05-23](https://forum.rclone.org/t/53838)). On Drive: "use --dir-cache-time 8760h" plus `--vfs-refresh` ([forum 54109, 2026-08-05](https://forum.rclone.org/t/54109)). On a non-polling remote, a low dir-cache time makes things slow ([forum 54067, 2026-07-23](https://forum.rclone.org/t/54067)). RcloneMount forces 15 s on every remote so that files written by its own jobs appear quickly. *Build:* use a long dir-cache time on remotes that poll for changes, and make the value a per-mount field for the rest. When a RcloneMount job writes to a remote that is also mounted, call `vfs/refresh` on that mount for the destination folder. That keeps the original goal without re-listing every 15 s. Add "Refresh listing" to the mount right-click menu. Check rclone's per-backend change-polling support before you pick the list.

**6. VFS cache controls and a disk-fill guard.** *Competitors:* Mountain Duck limits cache size per bookmark ([docs](https://docs.mountainduck.io/mountainduck/connect/sync/)). RClone Manager has per-mount VFS profiles. Rclone Explorer and AlphaCloudSync offer simple mode presets. *Why users care:* complaint #4. A user of Rclone UI asked for exactly one missing thing, a `--cache-dir` option ([forum 52568, 2026-03-04](https://forum.rclone.org/t/52568)). RcloneMount defaults to `full` with no size cap and no free-space floor; `--vfs-cache-min-free-space` is off by default ([mount docs](https://rclone.org/commands/rclone_mount/)). *Build:* add a cache-folder picker, a max size and a default minimum free space. Show cache use per mount. Name the presets in plain words. Warn when `full` mode points at a FAT or exFAT disk, which lacks the sparse files that mode uses (same docs).

**7. Keep-awake and a shutdown guard.** *Competitors:* RClone Manager calls `SetThreadExecutionState` and `ShutdownBlockReasonCreate` (v0.3.2, 2026-08-24, after request [#282, 2026-08-07](https://github.com/Zarestia-Dev/rclone-manager/issues/282)). Rclone Explorer keeps the PC awake. Mountain Duck 5.3.2 suppresses sleep during transfers ([2026-08-25](https://mountainduck.io/changelog/)). *Why users care:* a laptop that sleeps at 03:00 kills the nightly job. A Mountain Duck reviewer complained that the app blocked sleep until reboot ([App Store](https://apps.apple.com/us/app/mountain-duck/id1024974133)), so the block must always be released. *Build:* set `ES_CONTINUOUS | ES_SYSTEM_REQUIRED` while a job runs or uploads are pending, and clear it in `finally`. Give a shutdown block reason when uploads are pending.

**8. Schedules beyond daily.** *Competitors:* RClone Manager offers cron, at startup and a folder watcher. Rclone Explorer offers every N minutes or hours, daily and chosen weekdays. Rclone UI offers hourly, weekly and cron. Air Explorer and RcloneView charge for scheduling. *Why users care:* a user wanted faster than every 5 minutes ([RM #204, 2026-05-22](https://github.com/Zarestia-Dev/rclone-manager/issues/204)). Today, a user who types "weekly" gets nothing and no error. *Build:* replace the text box with a picker: daily at, chosen weekdays at, or every N minutes or hours. Validate the input and show the next run on the Jobs tab. Skip cron syntax. Windows Task Scheduler (M) can wait until users ask.

**9. Bandwidth and rate limits for mounts and the whole app.** *Competitors:* RaiDrive sells separate upload and download limits per drive (Starter plan and up). Rclone Explorer has a global timetable. Rclone Browser NG can change the limit of a running transfer. *Why users care:* Rclone UI users asked for an app-wide bwlimit ([forum 52568, 2026-03-18](https://forum.rclone.org/t/52568)). "bwlimit" returns 49 forum topics since 2025. An Air Explorer user hit HTTP 429 with no throttle option ([2026-06-22](https://fi.trustpilot.com/review/airexplorer.net)). OneDrive users run `--tpslimit 50` ([forum 53844](https://forum.rclone.org/t/53844)). *Build:* add a mount bwlimit field (upload:download), a tray "Throttle" toggle that calls `core/bwlimit` on every running rc port, and an optional tpslimit field.

**10. rclone rollback and version hold.** *Competitors:* Rclone UI's version manager (3.7.0, 2026-07-11). CryptBridge pins rclone 1.75.2. *Why users care:* complaint #8, most recently the 1.76.0 UNC hang ([forum 54517, 2026-11-17](https://forum.rclone.org/t/54517)). *Build:* keep the previous `rclone.exe` on update and add "Roll back" and "Hold this version". Keep a floor: the README requires 1.76+, and OneDrive Business needs 1.76+ before 2027-04-01 ([changelog](https://rclone.org/changelog/)).

**11. Network-drive toggle and an elevation warning.** RaiDrive charges for the local-disk versus network-drive choice ([pricing](https://www.raidrive.com/pricing)). rclone's docs suggest `--network-mode` when programs freeze on a fixed drive ([mount docs](https://rclone.org/commands/rclone_mount/)). Drives made by an elevated process are invisible to normal Explorer ([forum 52120, 2025-08-01](https://forum.rclone.org/t/52120)). *Build:* add a per-mount checkbox, and warn at start if the app runs elevated.

**12. winget / Scoop listing.** RClone Manager is in winget, Chocolatey and Scoop. Rclone UI, RcloneView and Rclone Browser are in winget too. RcloneMount did not appear in `winget search rclone` (run 2026-11-24). A user asked RClone Manager for package-manager installs ([#26, 2025-10-13](https://github.com/Zarestia-Dev/rclone-manager/issues/26)).

**13. Copy share link.** ExpanDrive, Mountain Duck, Rclone UI, Air Explorer and Rclone Browser all offer one. No user demand was found beyond vendor feature lists, so this ranks last. An action on the mount row with a file picker is S–M. A real Explorer context menu is L.

**Skipped, and why:** a built-in file browser (Explorer on the mounted drive already does this, and the forum complaint about RClone Manager shows the cost of a busy UI), `rclone serve`, a visual workflow builder, AI/MCP, mobile apps, remote or headless rclone backends, localisation and folder-watch triggers. All of these are breadth that would pull RcloneMount away from "mount and forget". Also skipped: Cloud Files API placeholders and offline pinning (L; they need a file-system layer other than WinFsp; watch OpenCfDrive), a Windows service for mounting before login, and multi-user file locking (rclone has no equivalent).

## Where RcloneMount already wins, and what to protect

RcloneMount gives away the set-and-forget features others charge for or lack. Auto-mount at start, remount after sleep or network return, and the detach watchdog are free. RcloneView charges for "auto re-mount on startup" ([pricing](https://rcloneview.com/src/pricing.html)). RClone Manager "will only try once per startup" and "will not continuously … reconnect" ([mounting docs](https://github.com/Zarestia-Dev/rclone-manager-website/blob/HEAD/public/docs/user-guide/mounting.md)). Rclone UI's Windows automount was buggy through 2026 ([#115](https://github.com/rclone/rclone-ui/issues/115), [#211](https://github.com/rclone/rclone-ui/issues/211)). Scheduling is free too. RcloneView Plus, Air Explorer Pro and Ultra Explorer Pro all charge for it. None of the mount-only tools has a transfer queue, bisync, check or cryptcheck; NetDrive says this is out of scope ([2026-10-19](https://www.netdrive.net/blog/netdrive-vs-rcloneview-mount-or-transfer/)).

It also avoids the friction others create. There are no ads, no forced sign-in and no licence activation, unlike RaiDrive's mandatory sign-in ([2025-03-21](https://with.raidrive.com/t/raidrive-2025-3-0/9679)) and Rclone UI's device limits. Every rclone backend is writable with any number of accounts, unlike RaiDrive's read-only tiers, CloudMounter's big-three limit and Air Explorer's one account per cloud. Its bisync safety (resync gate, max-delete, check-access, conflict policy) and dry-run report answer the destructive-sync fear. Its security work is ahead of RClone Manager, which shipped fixes for exposed RC credentials and an unauthenticated headless UI in 2026-11 ([#359](https://github.com/Zarestia-Dev/rclone-manager/issues/359), [#360](https://github.com/Zarestia-Dev/rclone-manager/issues/360)). That work covers per-run RC auth, SHA256-checked rclone downloads, a signed-MSI check, the pipe ACL and redacted diagnostics. Native WinForms also avoids Rclone UI's "failed to create webview" on Windows 11 26300 ([#251, 2026-10-12](https://github.com/rclone/rclone-ui/issues/251)) and RClone Manager's console pop-ups ([#100](https://github.com/Zarestia-Dev/rclone-manager/issues/100)).

Protect three things. Keep the remount path robust on every resume, because it is the main reason to choose this app. Keep the UI small. Keep the tray icon easy to see.

## Conclusion

The category's weak point is trust in state, not missing features. Users leave apps that say "mounted" when they are not, that say "copied" when the upload has not started, or that skip a schedule without a word. RcloneMount already handles the hardest part of this: it detects and repairs dead mounts. Its next step is to report the rest truthfully: pending uploads, failed jobs, and a Drive remote about to lose its client_id. All three run on rc calls and tray balloons the app already uses, so gaps 1, 3 and 4 together cost less than one competitor feature such as serve or workflows.

The competitive threat is Rclone UI, not the paid tools. It carries the "official" label, ships weekly, and added reconnect detection, notifications and OS scheduling in 2026. RcloneMount should not answer with breadth. It should keep the free set-and-forget features that RcloneView charges for, and be the Windows app whose mounts stay up and whose state is always correct. A remount path that is measurably robust, plus the visibility gaps above, keeps that lead.
